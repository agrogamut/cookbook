# Engine Console Reorientation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the engine console from one unbroken vertical stack of ~15 form fields into a resizable two-pane workspace with grouped, collapsible controls and an always-reachable Search button.

**Architecture:** Purely presentational change in the Next.js frontend. `web/src/app/page.tsx` swaps its fixed two-column CSS grid for shadcn's `Resizable` panel group (the component CLAUDE.md's Screens table already names for this route). `web/src/components/profile-form.tsx` keeps every field, every handler and every submit payload byte-identical, but wraps the field blocks in `Accordion` sections and moves the submit button into a sticky footer. No Go code, no API contract, no engine behaviour changes.

**Tech Stack:** Next.js 16 App Router, React 19, Tailwind v4, shadcn/ui (radix-ui unified package), `react-resizable-panels`, vitest + @testing-library/react + jsdom.

**Spec:** `docs/superpowers/specs/2026-08-19-console-reorientation-design.md`

## Global Constraints

- **Never mention claude, anthropic, or ai** anywhere: not in code, comments, file headers, or commit messages. No attribution trailers of any kind. No co-author tags.
- **No emojis, anywhere.**
- **No client-side invention** (CLAUDE.md Frontend rule 8): the frontend never computes a nutrition figure, fills a blank with a default, or rounds a gap away. This plan changes layout only - do not "helpfully" add default values to any form control.
- **Safety fields are never hidden behind a collapsed section.** Age (engine step 1) and allergens (engine step 2) are the two hard filters and must be visible without a click. This is a safety boundary, not a layout preference.
- **Density first** (CLAUDE.md Frontend rule 2): compact row heights, `text-xs`/`text-sm`, mono for IDs and quantities. Do not add decorative spacing, gradients, illustrations, or animated transitions beyond what shadcn ships.
- **No decorative anything** (Frontend rule 1): if a pixel does not carry information or afford an action, it does not go in.
- Every submit payload field in `handleSubmit` stays exactly as it is. Adding, removing, or defaulting a field is out of scope.
- Verification for every task: `cd web && npm test` and `cd web && npm run build` both pass.

- [ ] **Step 1: Write the test file**

Create `web/src/components/profile-form.test.tsx`:

```tsx
import { fireEvent, render, screen, waitFor } from "@testing-library/react";
import { describe, expect, it, vi, beforeEach } from "vitest";
import { ProfileForm } from "./profile-form";

// ProfileForm loads six reference vocabularies on mount. Mocking the whole api module
// keeps the test off the network; the empty arrays are the honest shape for "the
// vocabularies loaded and contained nothing", which is what an unseeded database returns.
vi.mock("@/lib/api", () => ({
  getAllergens: vi.fn(() => Promise.resolve([])),
  getClinicalMarkers: vi.fn(() => Promise.resolve([])),
  getEnums: vi.fn(() => Promise.resolve({})),
  getRegions: vi.fn(() => Promise.resolve([])),
  getCuisines: vi.fn(() => Promise.resolve([])),
  getSpecialCareConditions: vi.fn(() => Promise.resolve([])),
  getProfileEngineInput: vi.fn(),
}));

describe("ProfileForm", () => {
  beforeEach(() => {
    vi.clearAllMocks();
  });

  it("shows the age field without any interaction", async () => {
    // Age is engine step 1, a hard filter and the only required field. It must never
    // sit behind a disclosure control.
    render(<ProfileForm onSubmit={() => {}} loading={false} />);
    await waitFor(() => expect(screen.getByLabelText(/age \(months\)/i)).toBeInTheDocument());
  });

  it("shows the declared allergens fieldset without any interaction", async () => {
    // Allergens are engine step 2, the other hard filter. Same rule as age.
    render(<ProfileForm onSubmit={() => {}} loading={false} />);
    await waitFor(() => expect(screen.getByText(/declared allergens/i)).toBeInTheDocument());
  });

  it("disables submit until an age is entered", async () => {
    render(<ProfileForm onSubmit={() => {}} loading={false} />);
    const submit = await screen.findByRole("button", { name: /search/i });
    expect(submit).toBeDisabled();
  });

  it("submits the entered age", async () => {
    const onSubmit = vi.fn();
    render(<ProfileForm onSubmit={onSubmit} loading={false} />);
    const age = await screen.findByLabelText(/age \(months\)/i);
    fireEvent.change(age, { target: { value: "8" } });
    fireEvent.click(screen.getByRole("button", { name: /search/i }));
    await waitFor(() => expect(onSubmit).toHaveBeenCalledWith(
      expect.objectContaining({ age_months: 8 }),
    ));
  });

  it("sends no undefined optional fields when only age is set", async () => {
    // The engine treats a present-but-empty filter differently from an absent one.
    // Nothing the operator did not fill in may reach the request as a value.
    const onSubmit = vi.fn();
    render(<ProfileForm onSubmit={onSubmit} loading={false} />);
    const age = await screen.findByLabelText(/age \(months\)/i);
    fireEvent.change(age, { target: { value: "8" } });
    fireEvent.click(screen.getByRole("button", { name: /search/i }));
    await waitFor(() => expect(onSubmit).toHaveBeenCalled());
    const payload = onSubmit.mock.calls[0][0];
    expect(payload.diet_type).toBeUndefined();
    expect(payload.allergens).toBeUndefined();
    expect(payload.region_culture).toBeUndefined();
    expect(payload.meal_type).toBeUndefined();
  });

  it("shows the running state while a search is in flight", async () => {
    render(<ProfileForm onSubmit={() => {}} loading={true} />);
    expect(await screen.findByRole("button", { name: /running engine/i })).toBeDisabled();
  });
});
```
